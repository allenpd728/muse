# Test spec — W1 event-stream IR (task #123)

Written 2026-08-23 by the completing agent, per TASK_WORKFLOW §6.

## Status of coverage

W1 shipped with 58 pytest tests in `tools/ir/tests/` that **pass today**:

- `test_conformance.py` — known-answer pins for the whole corpus: per-movement
  Bach (parts, exact note counts, exact tempo maps), Byrd (MIDI path, 3 parts,
  velocities present), Schubert (24,772 notes / 1,731 dynamics), Beethoven 5
  (12 parts / 13,675 / 431 dynamics / 2-4 meter), Beethoven 9 (52 parts /
  239,459 / 11,931).
- `test_musicxml.py` — ties, chords, grace notes, rests, backup/forward cursor,
  mid-part divisions change, accidentals, dynamics, hairpins, articulations,
  slurs/fermatas, .mxl container, `inferred_voice`; malformed-input failures.
- `test_midi.py` — full maps from meta events, part/track derivation,
  note_on/note_off pairing (incl. velocity-0 offs), control-track exclusion,
  default tempo/meter insertion; malformed-input failures.
- `test_model.py` — deterministic sort order and every validation hook.

Run: `pip install -r tools/ir/requirements.txt && cd tools/ir && python -m pytest`.

## Behaviors still needing coverage (gaps)

1. **Tick-accuracy, not just counts.** Current conformance pins counts and map
   contents; nothing pins *positions*. Add golden-vector tests: a handful of
   known notes per corpus work with exact (onset, duration, pitch, voice)
   tuples, plus `Work.duration_ticks()` per work. This is the property W4's
   diff tool will lean on.
2. **Grace-note onset semantics.** Grace notes currently share the cursor
   position with the following note and nothing checks whether the corpus's
   512 Schubert grace notes land musically sensibly. Pin a known passage.
3. **Multi-movement .mxl** — the Schubert file is one partwise document
   containing all four movements (no movement boundaries are represented in
   the IR). If S1 needs movement structure, W1 needs a construct for it; the
   test should pin whatever is decided.
4. **Slur/tie number collisions** — notations with multiple concurrent
   numbered slurs/ties are collapsed to flags by design; a test should pin
   that deliberate lossiness so a future change is visible.
5. **CI wiring.** No GitHub Actions workflow exists yet. When CI returns
   (AGENTS.md Build/test), the IR suite must run there; until then this gap
   is tracked here rather than in a broken workflow file.
6. **Negative-path corpus sweep.** Malformed-input tests are synthetic; add a
   fuzz pass (truncated/corrupted copies of real corpus files) to confirm
   every failure surfaces as `IRParseError`, never a hang or partial Work.
