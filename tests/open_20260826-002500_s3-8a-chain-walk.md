# Test spec — S3.8a lineage chain-walk/verify helper (task #251)

Written 2026-08-26 by the completing agent, per TASK_WORKFLOW §6.

## What landed (behavior under test)

`tools/muse_lineage/` (`lineage.py`, `cli.py`): `walk()` follows
`provenance.extends` / `provenance.seed_hash` backward through a store of
`*.seed.yaml` / `*.mockup.json` files (hash = SHA-256 of committed file
bytes); `verify_pair()` does explicit two-artifact checks. Per-hop states:
verified / missing / mismatch / root / cycle. The real chain is live:
`seeds/bwv227.1.v2.seed.yaml` now carries `extends` → v1's bytes hash
(v1 is byte-identical to `bwv227.1.seed.yaml`; either resolves — content
addressing, not path addressing).

## Coverage to write

Target: `tools/muse_lineage/test_lineage.py` (new; fixture files under
`tmp_path`), run with `cd tools && python -m pytest muse_lineage -q`.
CLI exit codes need a seam test alongside.

1. **Walk happy path.** A 3-revision fixture chain (v3→v2→v1) walks to
   root with all hops verified; JSON shape pinned (`ok`, hop keys).
2. **Missing.** Pointer naming a nonexistent hash → `missing`, exit 1,
   walk stops there (does not skip ahead).
3. **Mismatch.** `verify_pair` against a tampered parent → `mismatch`,
   exit 1; against the true parent → `verified`, exit 0.
4. **YAML coercion trap (regression).** A 64-zero extends value parses
   as int 0 — must report `missing`, NOT `root` (this bug shipped and
   was fixed in-flight; pin it).
5. **Root.** A seed with no `extends`/`seed_hash` → single `root` hop,
   exit 0.
6. **Mockup hop.** Fixture `.mockup.json` with `provenance.seed_hash` →
   walker resolves the parent seed and continues (the S3.8b seam).
7. **Real-chain pin.** `walk(seeds/bwv227.1.v2.seed.yaml)` over the repo
   `seeds/` store is all verified/root — drift here means someone edited
   v1 without re-stamping v2 (which is the chain working as designed;
   the test forces the re-stamp decision to be explicit).
8. **Cycle guard.** Unit-level only (content-addressed cycles are
   practically unconstructible): call `walk` on a rigged store or
   monkeypatch `find_by_hash` — verify the guard terminates and reports
   `cycle`. (Justification: this is the one place a mock is necessary —
   a real cyclic fixture cannot be written to disk.)

## Known gaps (acceptable)

- Store scan is O(files) per hop with per-file hashing — fine at corpus
  scale; revisit if the store grows large.
- `mismatch` in walk mode (finding the *intended* parent by naming
  convention) is deliberately absent — no filename heuristics.
