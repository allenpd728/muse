# Test spec — Batch 2 #16: intermediate representation (IR)

**Source task:** #16 (importer IR)
**Code under test:** `importer/ir.mjs`; fixture `importer/fixtures/ir-sample.json`.

Baseline coverage landed with the task itself (the definition of done required
unit round-trips): `tests/ir.test.mjs` — 45 checks covering pitch/spelling/tick
converters, `validateIR` error channels, `normalizeIR` canonicalization, and
the lossless fixture round-trip. This spec is for the coverage that remains.

## Behaviors to verify

- **Parser boundary conformance (blocked on #17/#18):** whatever the MIDI and
  MusicXML parsers emit must pass `validateIR` with zero errors, and
  `normalizeIR(parserOutput)` must be idempotent. Each parser lands one
  fixture asserting this.
- **Synthesis contract (blocked on #19):** synthesis consumes only IR fields
  documented in `docs/scope-importer.md` — no ticks, no seconds. Test via a
  normalize → synthesize pass over the parser fixtures asserting no
  tick/second-derived values leak into `material.motifs[].durations`.
- **Converter fuzzing:** property-style round-trip of `midiToPitch` /
  `pitchToMidi` across all 128 midi values (currently spot-checked at 8),
  and `spellingToMidi` across the diatonic steps × alters {-1, 0, 1} ×
  octaves -1..9 (in-range subset only).
- **Fixture drift:** `importer/fixtures/ir-sample.json` stays in sync with
  the validator — the round-trip check in `tests/ir.test.mjs` covers this
  today; the follow-up should keep it wired if the IR shape evolves.

## How to run

`npm test` — new suites land as `tests/*.test.mjs` and fold into the harness
automatically. Converter fuzzing belongs in `tests/ir.test.mjs`; parser
boundary checks land with #17/#18 as their own suites.
