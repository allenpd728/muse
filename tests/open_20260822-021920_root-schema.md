# Test spec — Batch 1 #11: root muse.schema.json

**Source task:** #11 (root schema tying the section schemas together)
**Code under test:** `schema/muse.schema.json`; suite `tests/root-schema.test.mjs`;
CLI sibling registration in `tools/validate.mjs`.

Task DoD cases landed: `node tests/root-schema.test.mjs` (8/8) plus
`npm test`. `tools/validate.mjs` resolves all section `$ref`s (siblings
pre-registered by `$id`) and validates a composed document.

## Behaviors to verify (already landed)

- Composed document spanning all seven sections validates through the root.
- `muse_version`, `metadata`, `globals` required; the rest optional-undeclared.
- `muse_version` must match the semver regex (plain `"0.1"` rejected).
- Unknown top-level member rejected (`additionalProperties: false` decision).
- Section-level errors surface through the root (`form.energy: 2` rejected).
- CLI: default schema arg compiles the real root; relative `$ref`s resolve
  (previously: `schema error: can't resolve reference ...`).

## Residual coverage this follow-up must add

- **Fixture-upgrade regressions:** the root being real invalidated the #3 harness
  fixtures (upgraded this session to full documents) — pin a regression that the
  fixtures stay root-conformant when section schemas tighten further.
- **Sibling-registration behavior:** a section schema dropped or renamed
  (e.g. `schema/metadata.schema.json` missing) must produce a readable error,
  not a silent skip (CLI currently swallows sibling load errors with an empty
  `catch` — decide and pin).
- **Root ↔ section duplication:** `muse_version` semver is duplicated at the
  root only; if the spec later moves versioning into a section, add a
  cross-check the two places don't drift.
- Edge: `renditions: []` (empty array) against the sibling root-ref — depends
  on whether the spec intends zero sanctioned renditions to be legal.
